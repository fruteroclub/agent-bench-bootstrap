# File contract

## Required source files

A standard bench-agent bootstrap pack contains these seven files:

1. `SOUL.md`
2. `IDENTITY.md`
3. `USER.md`
4. `AGENTS.md`
5. `MEMORY.md`
6. `HEARTBEAT.md`
7. `TOOLS.md`

Treat these as the minimum required operating pack unless the user explicitly defines a different contract.

## Optional companion files

Generate or preserve these only when useful:
- `README.md` for human orientation
- `IMPLEMENTATION-PLAN.md` for rollout instructions
- `memory/YYYY-MM-DD.md` files when the source pack intentionally includes seeded memory
- local workstream files only if the user explicitly includes them

## What each file governs

### `SOUL.md`
Voice, temperament, enduring posture, and style constraints.

### `IDENTITY.md`
Role, mandate, authority, scope, and boundaries.

### `USER.md`
Working relationship with the human counterpart and response preferences.

### `AGENTS.md`
Operating contract, startup behavior, workstream protocol, communication rules, and escalation boundaries.

### `MEMORY.md`
Durable context worth always loading. Keep this concise.

### `HEARTBEAT.md`
Proactive maintenance and quiet-mode rules.

### `TOOLS.md`
Local operational notes, account pointers, and durable workflows.

## Quality bar

A good pack is:
- internally consistent
- role-specific
- installation-aware without overfitting to one host
- concise enough to stay useful in context
- explicit about approval boundaries
- clear about brand or entity distinctions when they matter
